# Agents Anywhere 2.1.0

2.1.0 是接口更新（MINOR）：本版新增会话内单独停止子代理的端点和能力，并让附件元数据可以携带原图像素宽高。按[版本号规则](../versioning.md)，**所有端**的版本号统一为 2.1.0（Server、Connector、Web、Desktop、Android、iOS、DSH 插件），之后的修复继续按 PATCH 在各端独立递增。本记录不包含安装包，安装包停留在 2.0.3；打包发布时另记来源提交与文件摘要。

## 接口变化

### 单独停止子代理，主停止不再牵连后台

- Server 新增 `POST /api/v2/sessions/{session_id}/runtime/subagent/stop`，请求体为 `{"taskId": "..."}`，`taskId` 是会话 Agent 卡片上的运行任务 id。运行时不认识的 id 返回 `{"stopped": false}` 的普通结果，不是错误。
- 新增会话级能力 `session.subagent_control`。客户端应按有效能力显示或隐藏“单独停止”入口，不要按 provider 名称判断。
- `POST /api/v2/sessions/{session_id}/runtime/interrupt` 支持可选的 `preserveBackground` 字段（默认 `false`）：模型切换等流程传入 `true` 时，运行时停止当前回合但保留正在运行的后台子代理。不传该字段的调用保持历史语义（全部停止）。

### 附件元数据携带原图宽高

- `POST /api/v2/sessions/{session_id}/attachments` 新增可选表单字段 `dimensions`：JSON 数组，与 `files` 顺序对齐，元素为 `{"width": int, "height": int}` 或 `null`。数组缺省、格式错误、长度不符或数值非法（非正整数、超过 65535）时**整体忽略且不影响上传本身**。
- 上传响应中的附件对象新增可选 `width` / `height`（无尺寸时为 `null`）；create-and-start、发送消息和 steer 的 `attachments` / `timelineAttachments` 载荷在没有尺寸时**不出现**这两个键，与旧版逐字节一致。`InlineAttachmentRef`（create-and-start 内联附件）同样支持这两个字段。
- 语义是**原图像素尺寸**（EXIF 方向已校正后的显示宽高），不是展示尺寸；各端把它映射到自己的布局上限（例如 iOS 240×320 夹紧），互不绑定。
- 尺寸由客户端在上传时提供（iOS 经 ImageIO 解码，HEIC 天然支持）；服务端不做图像解码推断，缺失或非法一律落回各端自己的兜底（预置占位比例 + 按固有尺寸校正）。
- Connector 会把宽高带进用户消息的 timeline 附件元数据和 pending 消息记录，使历史重投影后的气泡与实时气泡尺寸一致。设备路径图（connector artifact）不做尺寸探测。

## 旧端降级

- 旧客户端对新 Server：`width` / `height` 是可选字段，旧客户端读到后应忽略未知字段而不是报错（JSON 载荷多字段不改变既有字段语义）；旧客户端不发 `dimensions`，服务端不记录尺寸，行为与 2.0.x 相同。
- 新客户端对旧 Server：旧 Server 不认识 `dimensions` 表单字段，上传照常成功，只是没有尺寸；客户端按无尺寸兜底显示。新客户端调用 `subagent/stop` 或读取能力前，应先按有效能力判断，旧 Server 不会返回 `session.subagent_control`。
- 旧 Connector 对新 Server：不认识 `preserveBackground` 的 Connector 保持历史全停语义；不识别 `width` / `height` 的 Connector 在 timeline 元数据里不带这两个键。新 Server 不依赖它们存在。
- 旧 iOS 客户端对新 Server：解码时忽略新增的可选字段，上传和消息流程不受影响。

## Server 与数据库

本版 Server 没有数据库迁移，revision 仍为 `v2_41`（schema version `2.41`），与 2.0.3 相同；升级步骤见[升级指南](../upgrading.md)。
