# Agents Anywhere 2.3.0

2.3.0 是一次接口更新（MINOR）：会话元数据新增可选的 `latestTurnId`，让“回合已结束”成为持久事实，不再依赖可能陈旧的运行时状态。按[版本号规则](../versioning.md)，所有端的版本号统一升到 2.3.0；本文档在安装包构建前只记录接口变化、各端最低配套版本和数据库迁移，安装包记录待发布时补充。

## 接口变化

- 会话对象 `SessionView` 新增可选字段 `latestTurnId?: string | null`（会话列表、详情、`/sessions/{id}/meta`、`/sessions/{id}/snapshot` 与实时 `session.meta.updated` 共用）。旧服务端不返回该字段，旧客户端忽略它。
- `session.turnEnded` 新增可选的 `turnEndContract: 1`。Connector 2.3.0 发送它，表示自己也会在历史/结算同步里发送 `lastTurnId`，Server 才把 live `turnId` 写入 `sessions.latest_turn_id`。2.2.0 Connector 的 `turnEnded` 已带 `turnId` 但不带该标志，Server 不写持久字段（只保留原有的 turn-end seq / unread 事实），客户端回退旧判据；这避免“live id 已写、history 永远不重键”的半升级状态。
- Connector 的 `timeline.sync` 通知接受可选 `lastTurnId` 与 `baseTurnId`（放在 metadata 或顶层，均可）。Server 用它播种会话的 `latestTurnId`，不产生 unread 或 usage 事件；已存值只在以下情况被替换：新值相同（no-op）；`baseTurnId` 等于已存回合（同一 scheduled 回合从临时 id 重键为确定性 id）；或同步标记 `rebased` 且不带 `baseTurnId`（重启/版本升级后的全链重建；Connector 只在最后可见回合已完成、或最后只有一个未回复的用户提示时才携带）。带 `baseTurnId` 的 rebased 同步仍必须满足 `baseTurnId` 等于已存回合。其他“旧回合晚到”的同步不会覆盖更新的 live id。
- Claude 的完成判定用 transcript 里该回合最后一条 assistant 的 `stop_reason`：`tool_use`/`pause_turn`/缺失都视为仍未结束；CLI 自己写下的 `[Request interrupted by user]` 标记（含 tool-use 变体）是该回合的终态，用户停止后的半截回复仍可复制。无 `baseTurnId` 的扫描/重建只有在“最后可见回合确实已完成”或“最后可见回合只有未回复的用户提示”时才播种上一回合，避免重启后用上一回合 id 覆盖更新的 live id。Connector 还会在 provisional scheduled 回合的 `turnEnded` 前持久化 live→history 锚：重启后的 rebase 用它修复 failed/open-final 回合，并带 `baseTurnId`，Server 只在该回合仍是已存值时替换。
- Command 回合的 settle 不带 `baseTurnId`，Connector 还在 `turnEnded` 前写入 `suppress` 锚；history/rebased 同步都不发布 `lastTurnId`，不会用上一回合 id 替换它的 opaque live id。compact marker 是 divider、不托管页脚。
- 契约只改 `session-snapshot-response` 的 `SessionView`（新增可选属性），协议版本仍为 1.0；`turnEndContract` 只存在于 Connector→Server 通知，不是客户端契约。

## 各端最低配套版本

| 端 | 最低版本 | 说明 |
| --- | --- | --- |
| Server | 2.3.0 | 新增 `sessions.latest_turn_id`，需要数据库迁移 `v2_50` |
| Connector | 2.3.0 | `session.turnEnded` 携带 `turnEndContract: 1`；Claude 的 settle/history sync 播种 `lastTurnId`（中断标记算终态），并在 provisional scheduled 回合持久化 live→history 锚、command 回合写 suppress 锚；Codex 的 `TimelineSource` 声明 `turnId` 并用 index 播种，历史投影 checkpoint 升版，升级后首次同步会重建一次。DSH 的 `source` 不新增 turnId。 |
| iOS | 2.3.0 | 用 `latestTurnId` 与行 `source.turnId` 判定回合结束；字段缺失时回退 2.2.0 的运行时状态判据。durable 边界可在 gate 未观测到结束时切开合并桶；旧页（`hasNewerItems`）不采用 durable 水位。 |
| Web / Desktop | 2.3.0 | 生成类型补 `latestTurnId`；其余既有生成偏差不在本版处理，无行为变化 |
| Android | 2.3.0 | 忽略新字段，无行为变化 |
| DSH 插件 | 2.3.0 | 只有版本号变化：不写入 DSH 的 `latestTurnId`，DSH 行也不新增 `source.turnId`（与 2.2.0 相同），客户端回退原判据 |

## 产品变化

- Claude / Codex 会话的复制/分享页脚在 Connector 重启、恢复窗口、后台子代理、scheduled 唤醒回合后不再依赖“运行时状态是否新鲜”来封口；回合结束的 id 由 Connector 在回合结束通知和历史同步中声明。
- 旧 Server：不返回 `latestTurnId`，新客户端回退 2.2.0 的运行时状态判据。
- 旧 Connector（2.2.0）：`turnEnded` 不带 `turnEndContract`，Server 不写 `latestTurnId`；settle/history sync 也不带 `lastTurnId`，所以字段保持为空、客户端回退。新 Server 不会出现“live id 已写入但旧 Connector 永远不重键”的半升级状态。
- 新 Connector + 旧 iOS：旧 iOS 不读 `latestTurnId`，封口判据仍是 2.2.0；但 Codex 行从 2.3.0 起首次携带 `source.turnId`，旧 iOS 会按 2.2.0 既有的 turnId 切桶规则处理它（这是 Codex 回合边界的修复，不是逐字节一致的旧行为）。Claude 行在 2.2.0 已经带 turn id。
- DSH：本版不改插件；`session.turnEnded` 不带 turnId，Connector 也不从 item 顶层推断 `source.turnId`。DSH 的会话级 `latestTurnId` 仍为空、行级 `source.turnId` 与 2.2.0 相同，页脚与切桶都继续使用原判据。
- 新 Server + 新 Connector + 新 iOS：`turnEnded` 与 settle/history sync 两个写者都声明同一契约，durable 封口在重启、恢复窗口、后台子代理和 scheduled 回合后都可用。

## Server 与数据库

2.3.0 的数据库 revision 为 `v2_50`（schema version `2.50`）。`v2_50` 只新增可空的 `sessions.latest_turn_id`，不回填；旧 Server 忽略该列，新客户端在字段为空时回退原判据。升级步骤见[升级指南](../upgrading.md)。
